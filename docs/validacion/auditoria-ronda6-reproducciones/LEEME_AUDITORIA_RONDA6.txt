FitStore POS · Auditoría de la ronda 6

Este paquete contiene el informe independiente, el mensaje para Claude, evidencias y reproducciones. No es una nueva versión del software y no contiene el proyecto completo. Usa el ZIP original fitstore-pos-ronda6.zip como fuente de la aplicación.

Leer primero:
- MENSAJE_PARA_CLAUDE_AUDITORIA_RONDA6.txt
- fitstore-pos/docs/AUDITORIA_RONDA6.md
- fitstore-pos/docs/validacion/auditoria-ronda6.json

Las suites oficiales pasan (38 unitarias, 77 integración compilada, 8 navegador), pero hay 3 hallazgos abiertos (1 P1 y 2 P2). Las reproducciones dirigidas comprueban el comportamiento observado, incluidos dos casos defectuosos; su resultado verde no es aprobación funcional.

Las rutas de los scripts reproducen el laboratorio usado: /workspace/auditoria-ronda6/fitstore-pos, API compilada 3006, API de actualización 3007, API R3 3008, tsx 3009, preview 4186; PostgreSQL local 5434. Para repetir en otro entorno, adaptar rutas, puertos y credenciales QA. Extraer el ZIP original dentro del mismo directorio de auditoría para completar fitstore-pos/. Las reproducciones no deben ejecutarse sobre datos de una tienda.

Instalación y comprobaciones:
1. Configurar una .env propia en fitstore-pos/ con DATABASE_URL de una base exclusiva de QA, JWT_SECRET nuevo, PORT=3006, WEB_ORIGIN=http://127.0.0.1:4186 y SEED_DEMO_PASSWORD=FitStore-Demo-2026!. No se incluye .env ni tokens en el paquete.
2. Instalar con pnpm install --frozen-lockfile; ejecutar pnpm db:generate, pnpm db:migrate y pnpm db:seed.
3. pnpm check; iniciar API compilada; FITSTORE_API_URL=http://127.0.0.1:3006/api pnpm test:integration.
4. Con Playwright/Chromium instalado, iniciar preview.mjs; FITSTORE_WEB_URL=http://127.0.0.1:4186 pnpm test:e2e.
5. pnpm exec vitest run --config ../pruebas/vitest.config.ts; ejecutar los probes necesarios sobre las bases y puertos aislados.

La actualización completa necesita además el código original R3 en /workspace/fitstore-pos. runtime.mjs carga el secreto QA de R6 para que una sesión creada en R3 sea comprobable después de migrar. legacy-preparar.mjs guarda un token temporal privado local que debe excluirse de cualquier intercambio. La evidencia del paquete ya incluye el antes y después, sin ese token.

El archivo auditoria-ronda6-integridad.json documenta la comparación de los 193 archivos originales. Las capturas creadas por la suite oficial se copiaron a auditoria-ronda6-capturas-oficiales/ y los PNG originales fueron restaurados. No se incluyeron node_modules, builds, base de datos, JWT ni archivo de entorno. El manifiesto enumera los archivos entregados y sus hashes.
